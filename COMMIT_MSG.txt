fix: 给一轮对话加终止性预算，解决「停不下来」

现象：Supervisor 认为任务没做完、反复派活，或 Critic 反复打回，一轮跑几分钟、
烧掉大量 token 却出不了结果。

根因不是死循环——两个循环本来都有上限（max_agent_hops / max_revisions），
但那两个上限只数「做了几次」，不数「花了多久」。模型慢的时候（例如推理模型
单次调用 20-30 秒），4 次跳转 + 2 次返工就是十多分钟。用户感知就是卡死。

修复：四个互相独立的刹车，任何一个先到就收尾。

1. FINAGENT_MAX_STEPS（默认 24）
   一轮最多执行多少个图节点，supervisor / 专家 / critic 各自 +1。
2. FINAGENT_MAX_TURN_SECONDS（默认 180）
   墙钟预算。_reset_turn 写入 time.monotonic() 基线，每次进 supervisor 检查。
3. FINAGENT_MAX_TOTAL_REVISIONS（默认 2）
   跨 Agent 的返工总额度。注意语义：0 表示「不返工」，不是「一步都不走」——
   所以这条只挡 critic 的返工，不参与整轮终止判断。
4. 返工无变化保护
   返工后的结论指纹与上一版相同 → 不再重审，避免两个节点来回打乒乓。

配套：
- 停下不抛异常，走 save_memory → risk_guard → finalize 正常收尾，把已有结论交付，
  并在 TurnResult.stop_reason 与决策轨迹里写明原因。
- 截断时 UI 显示黄色提示条、CLI 打黄字，明确告知「结论可能不完整」。
- recursion_limit 改为按 max_steps 推导（原来硬编码 60）。
- 修一个合并遗留 bug：_may_continue 里还引用已删除的 fundamental_analyst /
  technical_analyst，导致「深度分析」永远判定「可以继续」，白跑一轮 supervisor。
- doctor 显示当前预算。

测试：新增 test_termination.py 9 个用例（三重预算各自生效、跨 Agent 额度、
返工不乒乓、截断后仍有回答、正常轮不误判）。全量 376 passed。
