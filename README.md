## 它是什么

一个**可观察**的金融分析 Agent。你问「中国太保现在多少钱，最近一周走势和估值怎么样」，
它不会直接甩一段话给你，而是：

1. **规划** —— 把问题拆成「现价 / 走势 / 估值」三个必做项
2. **取数** —— 调行情工具，失败自动重试、切备用源
3. **计算** —— 区间涨幅由代码算，模型只负责解释
4. **审查** —— 逻辑（模型）、证据（代码）、风控（规则）三层各管一段
5. **交付** —— 缺哪项就明说，不拖累已拿到的数据

界面上你能看到每一次工具调用、每一条审查意见、每一步路由决策。这不是装饰，
是**审计证据**。

cd FinancialAI-Agent

# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate

## 为什么值得看

大多数「金融 Agent」的做法是：给模型一堆工具，让它自己决定调什么，最后用另一个
模型「审查」它。这套做法有两个天生的洞：

* **审查者也是模型**——它只能判断「这段话像不像有依据」，判断不了「这个数字对不对」
* **看不见过程**——出问题时你只知道结论错了，不知道哪一步错的

这个项目的三个核心设计，都是为了补这两个洞：

### 1. 证据由代码校验，不由模型校验

```
结论：贵州茅台近一月上涨 30%
      ↓
用工具返回的首尾收盘价重算 → 7.5%
      ↓
CONFLICTED → 阻断交付，要求返工
```

模型负责「解释走势」，**涨跌幅永远由代码算**。数字找不到出处、涨幅对不上、
数据过期，都会被判为不可交付。

### 2. 终止条件是枚举出来的，不是猜的

```
submit / budget_iterations / budget_tokens / budget_wallclock
tool_failure / model_failure / contract_violation / cancelled
```

「做完了」和「预算耗尽」是两件不同的事。前者 `completed`，后者 `partial` 并说明原因。
不会出现「模型不说话了，就当它答完了」。

### 3. 失败不会一刀切

「现价拿到了、走势没拿到、估值拿到了」——交付的是**部分成功**：正文照常给，
末尾写明「缺少：近期走势」。可选项（技术指标、资金流）失败则完全不影响交付。

## 架构

```
                     ┌────────────┐
   用户提问 ────────► │ Supervisor │ 规划 + 路由
                     └─────┬──────┘
             ┌─────────────┼─────────────┐
             ▼             ▼             ▼
        ┌─────────┐   ┌────────┐   ┌────────┐
        │ 研究    │   │ 量化   │   │ 预警   │   3 个 Agent
        │ Researcher│ │ Quant  │   │ Alert  │
        └────┬────┘   └───┬────┘   └───┬────┘
             └────────────┼────────────┘
                          ▼
                  ┌───────────────┐
                  │ Critic (LLM)  │ 逻辑与一致性
                  └───────┬───────┘
                          ▼
                  ┌───────────────┐
                  │ Evidence      │ 数字/涨幅/时效（确定性代码）
                  │ Validator     │
                  └───────┬───────┘
                          ▼
                  ┌───────────────┐
                  │ RiskGuard     │ 硬规则，不依赖 LLM 裁决
                  └───────┬───────┘
                          ▼
                     交付 / 部分成功
```

**三层执行控制**：

| 层 | 解决什么 | 机制 |
| --- | --- | --- |
| 预算 | 停下来 | 轮数 / token / 墙钟 / 工具数四重封顶 |
| Steering | 跑偏了 | 边跑边调：`cancel` / `narrow` / `brief` / `focus`，在 step 边界生效 |
| 恢复 | 断了 | 事件表判定阶段；重连按 `after=<seq>` 续播，不重跑 |

## 数据源

| 数据源 | 配置 | 费用 | 覆盖 |
| --- | --- | --- | --- |
| 东方财富（默认） | `FINAGENT_PROVIDER=eastmoney` | **免费** | 日线、实时、估值、指数、选股池 |
| 新浪（备用） | 自动切换 | 免费 | 实时报价、全市场列表 |
| 妙想 Skills | `MX_APIKEY` | 官方额度 | 财报、股东、资讯、自然语言选股 |
| Tushare | `FINAGENT_PROVIDER=tushare` | 需 token | 全量（含宏观、资金流） |

免费源会限流、会断连。所以 Provider 层有一整套策略：**能力预检 → 有限重试 →
指数退避 → 熔断 → 备用源 → 缓存 → singleflight**。45 个工具不用各自实现。

## 界面

新版工作台（`/ui`）是终端风格：白/深双色、等宽字体、无头像无渐变。

- **时间线**：每次工具调用一个圆点（橙=执行中 / 绿=成功 / 红=失败），点开看原始输出
- **流式渲染**：逐字输出，光标闪烁；代码块带 Copy
- **权限审批**：敏感操作（建仓、预警）执行前**真的会停住**，等你点「允许」；
  按钮有 200ms 防误触，支持 `y`/`n`
- **Ctrl+C 中断**：同时停前端流和后端执行，已完成的部分保留

经典界面保留在 `/classic`。

## 它做不到什么

诚实比包装重要。这些是真实短板：

**数据层**
- 免费源没有财报公告日，回测里可能构成前视偏差（已标 `REPORT_PERIOD_UNKNOWN`）
- 估值只有最新一行，没有历史 PE 分位
- 港股/美股覆盖有限

**回测层**
- 涨跌停按收盘价判定，没有盘口撮合
- 没有大单冲击的微观结构模型（只有平方根近似）
- 复权因子链的连续性检测是启发式的

**Agent 层**
- Critic 抓不住「推理逻辑错误」，只能抓数字和一致性
- 证据校验只覆盖数字，覆盖不了「这个结论合不合理」
- 部分成功判定靠关键词，长句复合意图可能漏判

**工程层**
- 单机、无鉴权、无多租户
- SQLite 存档，没做水平扩展
